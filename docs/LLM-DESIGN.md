# 阶段 2 设计：玩家对战大模型

> 状态：**已实现**（2026-10-11）。实现与草案的差异见文末「实施记录」。
> 阶段 3（大模型对战大模型）会复用这里的大部分模块，设计时一并考虑。

## 目标

- 玩家可以和任意一个大模型下一局象棋大乱斗
- 大模型会「说话」：玩家每走一步，它先点评玩家这一步和局势，再落子。它**不透露自己的打算**，思考过程对玩家隐藏
- 尽量多兼容模型：Anthropic 接口，以及各家 OpenAI 兼容接口
- API 密钥只存在玩家自己的浏览器里，请求由浏览器直接发给模型服务商，不经过任何我们的服务器
- 模型不管输出什么，对局都不会卡死或走出违规棋

不做的事：不训练模型；不提供代付或中转服务；不承诺模型棋力（大模型下棋普遍偏弱，这个模式主要是好玩）。

## 一步棋的流程

```
玩家行动（走子 / 选锦囊）
   │
   ├──► 请求 A：发言 ──► 对话气泡显示
   │     （只看局面和玩家刚才做了什么）
   │
   └──► 请求 B：走棋 ──► 解析编号 ──► 等发言显示完 ──► 落子
         （看局面 + 合法走法列表 + 私有备忘，思考对玩家隐藏）
```

**A 和 B 同时发出**，原因有两个：

1. **防止泄露打算**：发言请求里没有合法走法列表，模型在说话时也还没做决定。即使它想剧透也没有东西可剧透，比单靠提示词要求「不准透露」可靠得多
2. **快**：两个请求的等待时间重叠，总耗时约等于较慢的那个

落子时机：B 返回后，如果发言还没显示，或者显示还不到 1.5 秒，就再等一会儿，保证「先说话后落子」的观感。发言请求失败时直接落子，不提示错误（发言是锦上添花）。

### 发言的范围

发言点评的是「上次大模型行动之后，玩家做的所有事」。这可能包括走子、选锦囊、额外行动，以及护盾挡刀、复活之类由此触发的事件，取自对局日志。

其他时机：

- 大模型执红先手的第一步：说一句开场白
- 对局结束：说一句结束语（赢、输、和各有不同的提示）
- 大模型自己的额外行动（回马枪、兵贵神速）：不额外发言

### 隐藏的思考

「思考」有两种来源，都不显示给玩家：

- **模型自带的推理**：Claude 的 extended thinking、DeepSeek-R1 的 `reasoning_content`、OpenAI o 系列等。设置里提供「思考强度」选项，映射到各家的参数；模型不支持时忽略
- **输出里的 `analysis` 字段**：走棋请求要求模型先写简短分析再给编号，对不支持推理的模型也有一点「先想后走」的效果

开发模式下，界面上有调试面板能看到这些内容，方便调提示词。正式界面要不要在**对局结束后**揭晓，见文末待定问题。

## 接入层

不用 LangChain / LangGraph。我们的需求只是「发一条消息、拿一段文本或 JSON」，自己写更轻，也更容易处理各家的差异。

```ts
interface LlmClient {
  complete(req: {
    system: string
    user: string
    /** 需要结构化输出时提供，适配器按能力降级 */
    schema?: JsonSchema
    maxTokens: number
    reasoning?: 'off' | 'low' | 'medium' | 'high'
    signal: AbortSignal
  }): Promise<{
    text: string
    reasoning?: string
    usage: { input: number; output: number; cached?: number }
  }>
}
```

两个适配器：

| 适配器 | 实现 | 说明 |
|---|---|---|
| Anthropic | 官方 `@anthropic-ai/sdk`，开启 `dangerouslyAllowBrowser` | 首次使用时动态加载，不增加主包体积。系统提示词加 `cache_control` 缓存 |
| OpenAI 兼容 | 手写 `fetch` | 地址可自定义，覆盖 OpenAI、DeepSeek、Gemini、OpenRouter、智谱、硅基流动、火山方舟、本地 Ollama 等 |

### 浏览器能否直连（CORS）

2026-10-11 用预检请求实测，Origin 为 `https://wervex.github.io`：

| 服务商 | 结果 |
|---|---|
| Anthropic | ✅ 需要带 `anthropic-dangerous-direct-browser-access` 头，SDK 会自动加 |
| OpenAI | ✅ |
| DeepSeek | ✅ |
| Google Gemini（OpenAI 兼容地址） | ✅ |
| OpenRouter | ✅ 可以间接使用很多不支持直连的模型 |
| 智谱 | ✅ |
| 硅基流动 | ✅ |
| 火山方舟（豆包），含 Coding Plan | ❌ 预检看似通过，但实际请求不允许带 `authorization` / `x-api-key` 头，浏览器会拦截（真实浏览器中验证） |
| Moonshot（Kimi） | ❌ 预检没有返回允许跨域的头，可改用 OpenRouter 或硅基流动上的 Kimi |
| 阿里云百炼（通义） | ✅ 在真实浏览器中验证 |
| 本地 Ollama / LM Studio | ❓ 需要用户设置允许的来源（如 `OLLAMA_ORIGINS`）；Chrome 访问本地网络可能弹出授权提示 |

预检通过不代表一定可用，正式请求还要再验证一次。设置界面的「测试连接」会用一次极小的请求，同时检查密钥、跨域和支持的输出格式（见下节）。

### 输出格式分级兜底

走棋请求要求模型返回 `{"analysis": "...", "memo": "...", "move": 12}`：

1. **JSON Schema**：Anthropic 用结构化输出或强制工具调用（开启思考时用前者，两者在思考模式下的兼容性实施时再确认）；OpenAI 兼容接口用 `response_format: json_schema`
2. **JSON 模式**：`response_format: json_object`，DeepSeek、智谱等大多支持
3. **纯文本**：要求最后一行写 `走法: 12`，用正则提取。也会尝试从文本里找出 JSON 块
4. **重试一次**：把解析失败的原因（例如「编号 87 不存在，范围是 1–64」）附在消息里再请求一次
5. **兜底走法**：仍然失败就由程序代走，日志里标明「（兜底）」。兜底方式见待定问题

「测试连接」会记住这个配置支持到哪一级，之后直接从那一级开始。某一级返回 400 之类的「参数不支持」错误时，自动降一级并记住。

选锦囊用同样的机制，返回 `{"choice": 2}` 或 `{"choice": "reroll"}`。

### 错误处理

| 情况 | 处理 |
|---|---|
| 密钥错误、余额不足、模型名错误 | 暂停对局，弹出错误原文。可以修改设置后继续，也可以「由规则 AI 接管」把本局下完 |
| 超时（默认 90 秒，可设置） | 重试一次，再失败就兜底 |
| 限流（429） | 按 `retry-after` 等待后重试 |
| 网络断开 | 同密钥错误：暂停，让玩家选择 |
| 玩家悔棋、退出 | 用 `AbortController` 取消进行中的请求 |

思考中的提示会显示已等待的秒数，并提供「跳过，随便走一步」按钮。推理模型一步要想一两分钟时，玩家不至于干等。

## 提示词

### 每步独立请求，不累积对话

每次请求都重新构造完整的提示词，不把前面的对话发回去：

- **不会超出上下文**：一局 150 回合也只是每次几千 token，对小上下文的模型同样适用
- **省钱、可缓存**：系统提示词固定不变，各家的前缀缓存都能命中
- **方便阶段 3**：每个模型只看到自己的系统提示词、公开局面和自己的备忘，天然看不到对手的发言和思考

连续性靠**私有备忘**：走棋请求的输出里有 `memo` 字段（最多 200 字），下一步原样放回提示词。模型可以在里面记计划，例如「准备用炮打中路」。备忘只给模型自己看，玩家看不到，发言请求里也不包含，避免它在发言时念出来。

### 系统提示词（固定，可缓存）

1. 角色与任务：你在下象棋大乱斗，你的目标是吃掉对方的将帅
2. 基本规则：中国象棋走法；吃将获胜，不禁止送将；飞将；无棋可走判负；三次重复或 150 回合判和
3. 坐标说明
4. 护盾规则
5. **全部 29 个锦囊的说明**，从 `AUGMENT_LIST` 自动生成，与游戏内文字一致
6. 人设（见「界面」一节）

估计 3500–4500 token。放全部锦囊而不是只放场上出现的，是为了让系统提示词整局不变，从而命中缓存。

### 局面表示

坐标沿用象棋程序通用的 UCCI 写法：列 a–i 从左到右，行 0–9 从红方底线往上数。红帅开局在 e0，黑将在 e9。引擎内部的 `y` 方向相反，渲染时换算。

同时给出棋盘图和棋子清单。棋盘图便于模型看清相对位置，清单便于准确定位：

```
第 12 回合，轮到你（黑方）走。距离下次锦囊：第 16 回合。

    a  b  c  d  e  f  g  h  i
 9  車 ・ 象 士 將 士 象 ・ 車
 8  ・ ・ ・ ・ ・ ・ ・ ・ ・
 7  ・ 砲 馬 ・ ・ ・ 馬 ・ ・
 ...
 0  俥 傌 相 仕 帥 仕 相 ・ 俥

红方：帥 e0；俥 a0 i0〔盾〕；傌 b0；炮 e2 ...
黑方：將 e9〔盾〕；車 a9 i9；...

红方锦囊：铁甲战车、连珠炮
黑方锦囊（你）：天马行空、空城计（剩余 1 次）
刷新次数：你 1，对方 0
子力：红 46，黑 41
```

### 走棋请求的用户消息

```
〈局面，同上〉

最近的走法：
  第 10 回合 黑：马 c7→d5
  第 11 回合 红：炮 h2→h9 吃 车（被护盾挡下，护盾消失）
  第 11 回合 黑：车 a9→a7
  第 12 回合 红：炮 e2→e6 吃 卒

你上一步留下的备忘：
  对方炮在中路，下一步考虑用马回防 e7。

合法走法（共 38 个，只能从中选一个，回复编号）：
   1. 將 e9→d9
   2. 車 a7→a8
  ...
  17. 馬 d5→e7
  18. 馬 d5→f4  ⚠走后將可被吃
  ...
  25. 砲 b7→b0 吃 傌（对方有护盾，会被挡下）
  ...

请先简要分析（不超过 150 字），再给出走法编号，
并写一条给自己下一步看的备忘（不超过 200 字）。
输出 JSON：{"analysis": "...", "memo": "...", "move": 编号}
```

走法按棋子分组排列，便于模型查找。轮到额外行动且可以跳过时，列表最后加一项「跳过」。

**辅助标注**（设置里可以开关，默认开）：引擎给每个走法附上可以直接算出来的事实，不含引擎自己的判断。

- `⚠走后將可被吃`：走完后对方能直接吃将
- `将军`：走完后能吃对方的将，或者能攻击到将但会被挡下
- `会被挡下`：吃的目标有护盾或锦囊保护
- `走后被吃`：走到的格子会被对方直接吃掉，而且没有保护（不考虑交换是否划算）
- `重复局面`：走完后局面已经出现过两次，再出现就判和

关掉辅助标注就是「裸考」，可以用来比较模型的真实棋力。

### 发言请求的用户消息

```
〈局面〉

上次你行动之后，对方：
  - 选择了锦囊「连珠炮」
  - 炮 e2→e6 吃 卒

请用 1–2 句话（不超过 60 字）点评对方这一步和当前局势。
只评论已经发生的事，不要提你接下来打算怎么走。
直接输出要说的话，不要任何格式。
```

发言请求还会附上几条引擎算出的事实，例如「这一步吃掉了你的卒」「这一步之后你的 i9 车被炮瞄着」，让发言有依据，不至于胡说。发言请求不需要 JSON，所有模型都能用。

### Token 用量估算

一局按大模型走 60 步算，约 120 次请求：

- 走棋请求：系统提示词约 4k + 用户消息约 2.5k
- 发言请求：系统提示词约 4k + 用户消息约 1.5k
- 一局输入约 70 万 token，其中约 48 万是可缓存的系统提示词；输出约 2–3 万 token（不含模型自带的推理）

界面会显示本局累计用量（取自接口返回的 usage），不估算价格，因为各家价格差别太大、变化也快。实施后用真实对局校准这些数字。

## 密钥与隐私

- 配置（服务商、地址、模型名、密钥）存在 `localStorage`，可以存多套，阶段 3 要选两个模型对战。也可以勾选「只在本次打开时有效」，改存 `sessionStorage`
- 密钥**不会**出现在回放、日志、URL、错误上报里；调试面板也会把它打码
- 设置界面写明风险：
  - 用这台电脑、这个浏览器的人能读到密钥
  - 建议在服务商后台单独建一个有额度上限的密钥
- 已知限制：GitHub Pages 上同一个用户的所有项目共用 `wervex.github.io` 这个域名，它们之间能互相读取 localStorage。目前那个域名下只有我们自己的项目，之后如果用自定义域名就没有这个问题

## 界面

**入口**：在「人机对战」的设置页加一个「对手」切换：`规则 AI | 大模型`。选大模型后，显示模型配置和以下选项。

- **模型配置**：
  - 服务商预设（自动填地址、推荐模型名）、密钥（默认隐藏，可切换显示）、模型名
  - 思考强度、超时
  - 「测试连接」按钮
- **辅助标注**：开 / 关
- **发言**：开 / 关。关掉可以省一半请求
- **人设**：几个预设加一个自定义输入框，只影响说话风格，不影响走棋请求。预设例如：
  - 冷静解说
  - 嘴硬棋手
  - 古风谋士
  - 热血新人

**对局中**：

- 对话气泡显示在大模型一侧的玩家名附近，新的一句会替换旧的。完整的发言记录和对局日志放在一起，按时间排列
- 思考中：显示「〈模型名〉思考中… 23 秒」和「跳过」按钮
- 状态区显示本局累计 token 用量、兜底次数（例如「3 步为程序代走」），棋力表现是否掺水一目了然
- 走法提示（💡）照常可用，悔棋同人机对战：连同大模型的应对一起撤回，被撤回的那几句发言也一起移除

**回放**：模式记为 `llm`，玩家名写模型名。发言要不要存进回放，见待定问题。

## 代码结构

```
src/llm/
  types.ts        # LlmClient 接口、配置类型
  anthropic.ts    # Anthropic 适配器（动态加载 SDK）
  openai.ts       # OpenAI 兼容适配器
  presets.ts      # 服务商预设
  settings.ts     # 配置的读写（localStorage / sessionStorage）
  notation.ts     # 坐标与走法的文字表示
  prompt.ts       # 系统提示词、局面、走法列表、发言请求的构造
  annotate.ts     # 辅助标注
  parse.ts        # 输出解析与分级兜底
  player.ts       # LlmPlayer：comment()、decide()，管理备忘、重试、兜底
src/ui/
  LlmSetup.tsx    # 模型配置界面
  LlmGame.tsx     # 对局（复用 GameView），或者扩展现有的 AiGame.tsx
  Speech.tsx      # 对话气泡
scripts/llm-match.ts  # 命令行：大模型对规则 AI，用于调提示词（密钥从环境变量读取）
```

`LlmPlayer` 不依赖 React，和规则 AI 的 `BotClient` 地位相同。阶段 3 就是两个 `LlmPlayer` 轮流行动。

## 待定问题

请逐条给个意见：

1. **入口**：放在「人机对战」里作为对手选项（我的建议，入口少一点更清爽），还是首页单独一个「大模型对战」按钮？
2. **兜底走法**：之前定的是随机走一步。我建议改成由规则 AI 的「入门」难度代走：同样不会卡住，但不会出现随机送子把对局搞得很难看的情况。兜底次数会显示在界面上，不会掺水
3. **对局结束后揭晓思考**：对局中隐藏的分析和备忘，要不要在结束后提供「复盘」查看（每一步它在想什么）？我觉得这是个很有意思的看点，对局中依然完全隐藏
4. **发言存进回放**：分享的回放里带上大模型的发言会更有传播性。代价是链接变长：中文发言整局大约多出十几 KB，微信里可能发不出去。可选做法：
   - 只在下载的回放文件里带上
   - 或者压缩后放进链接
5. **调提示词用的密钥**：第 1 步需要用真实模型下几局来调提示词。你方便提供一个测试用的密钥吗（例如 DeepSeek，便宜）？密钥只通过环境变量传给本地脚本，不写进任何文件。一局大约 70 万输入 token，调试估计跑 5–10 局。如果你不想提供，我就只用假的客户端把流程做通，提示词由你试玩后反馈再调
6. **优先保证哪几家**：你自己或朋友主要用哪些模型？我会优先把它们的预设和输出格式测通

4. 发言与思考存进回放文件，大小控制在 10MB 以内（实际一局只有几十 KB）
5. 用火山方舟 Coding Plan（DeepSeek V4.1 Flash）调试
6. 只做 Anthropic 和 OpenAI 两种接口，配置为「接口地址 + 密钥 + 模型名」，模型名可以自动获取或手动填写

与草案的差异：

- **不用 Anthropic 官方 SDK**：SDK 会附带 `x-stainless-*` 请求头，第三方兼容接口的跨域设置大多不允许这些头。两种接口都用 fetch 手写
- **输出格式只分两级**：OpenAI 兼容接口先尝试 JSON 模式，不支持就去掉；Anthropic 接口直接要求输出 JSON。解析端兼容代码块、前后的说明文字、`<think>` 标签和「走法：12」这类写法。JSON Schema 各家支持差异大，收益不明显，没有做
- **本地转发**：火山方舟、Kimi 不允许网页直连，新增 `npm run llm-proxy` 和开发服务器内置的转发，设置里填「转发地址」即可
- **思考强度**：Anthropic 接口可以选「关闭」；OpenAI 兼容接口各家关闭思考的参数不统一，改为提供「额外参数（JSON）」，由预设提示具体写法
- **辅助标注**：增加了「你的棋子正受到的攻击」一节（含有无保护），走法标注增加「直接获胜」「攻击将帅（会被挡下）」

调试中发现的问题：

- DeepSeek（Coding Plan）默认深度思考，一步要想几十秒，4096 token 的输出上限会被思考用完，回复为空。输出上限提高到 8192，被截断时给出明确提示；`budget_tokens` 对它不起作用，实际可用的设置是关闭思考（每步约 2 秒）
- 模型会自己推算「炮能不能吃」并算错。系统提示词里强调「能吃的子都已在列表中写明，直接查列表」
- 一步棋触发锦囊发放时，局面进入选锦囊阶段，送将标注漏判，已修复并加了测试

### 第二轮调整（用户试玩反馈）

反馈：OpenAI 兼容接口没有「关闭思考」，有的模型思考很长；关闭思考后又下得很差，被叫杀也不防。

- **关闭思考**：标准的 `reasoning_effort` 很多家不认（实测火山方舟对 low / minimal 都照样思考），关闭思考的参数各家不同。「关闭」按地址自动选择：
  - 火山方舟、智谱、DeepSeek：`thinking: {type: "disabled"}`
  - 通义、硅基流动：`enable_thinking: false`
  - OpenRouter：`reasoning: {enabled: false}`
  - OpenAI、Gemini：`reasoning_effort: "none"`
  - 其他地址两种常见写法都带上。服务商返回参数错误时自动去掉并记住，测试连接会提示
- **战术检查**：棋下得差的根本原因是模型自己算不了几步。改为让规则引擎（`scoreMoves`，后台线程约 1 秒，搜索 4 层）给每个走法打分，在走法列表里标出：
  - ⚠会被强制吃将
  - 吃亏约 N 分：比最好的走法差 2.5 分以上
  - ★能强制吃将
  - 被叫杀时，在列表前直接写明「只有编号 x、y 能避免被强制吃将」
- 辅助从开关改为四档：裸考 / 基础标注 / 战术检查（默认）/ 引擎推荐（再标出引擎的前三步）
- 有战术检查时，提示词告诉模型"不需要长时间推演"，减少推理模型的思考时间
- **两步杀检查**：搜索时间只有约 1 秒，实测一半局面只算到 3 层，看不到"对方将一军、怎么应都会被吃将"。另加专门的检查，只展开将军的走法，几乎不花时间
- **再确认**：关闭思考的模型经常看到了 ⚠ 标注照样走（日志里甚至写着"但标注送将"）。现在模型选了送将、会被强制吃将、或吃亏 4 分以上的走法，而且还有别的选择时，程序会把原因告诉它，请它确认一次；坚持就按它的走。每局大约触发 2–6 次
- 实测（DeepSeek V4.1 Flash，关闭思考，对规则 AI「普通」）：只有基础标注时，两局分别在第 3、10 回合结束，其中一局是模型明知送将照样走；加上战术检查和再确认后，对局能撑到 50 多回合，输在长期的子力劣势和中途发放锦囊带来的变化（引擎也无法预见对方会抽到什么）

实际用量（关闭思考、开启发言，模型执黑约 12 步）：输入约 5.7 万 token（缓存命中约 2.5 万），输出约 2400 token，远低于草案的估算。

### 第三轮调整（模型对战实测）

- **关闭思考要按模型试**：火山方舟上，DeepSeek 认 `thinking: disabled`，对 `reasoning_effort: minimal` 照样思考；GLM 在 Anthropic 接口上不支持关闭思考，在 OpenAI 兼容接口上只认 `reasoning_effort: minimal`。现在「关闭」按地址给出几种候选写法，逐个尝试并记住对这个模型有效的那种（`thinkingOffCandidates`）。火山方舟 Coding Plan 预设改为 OpenAI 兼容接口
- **「低 / 中 / 高」基本无效**：这两个模型都不遵守思考预算，选「低」一步要想 1–3 分钟，还常常想到输出上限、给不出答案；在提示词里要求"思考简短"也没用。实测关闭思考后 DeepSeek 每步约 3 秒、GLM 约 5 秒
- **超时不重试**：等到超时直接由规则 AI 代走并说明原因，不再白等第二轮
- **结构化输出 + 作战笔记**：走棋回复改为固定结构（局面判断、当前策略、走法、理由、接下来的计划、要提防的威胁）。策略、计划、提防作为作战笔记放回下一步的提示词，再附上自己最近三步的决策和理由，让模型先检查计划还成不成立。
  没有用多轮对话：那样每步都要重发之前所有的提示词，一局下来上下文会到几十万 token，费用成倍增长，小上下文的模型也装不下；结构化笔记做到了连贯，上下文长度固定，也不影响缓存
- **发言降火**：以点评棋盘为主，锦囊只在刚改变局面时才提；对喷模式下可以接一句，但不要变成吵架。「嘴硬棋手」改为点到为止的调侃
- **界面**：对局里只显示玩家起的配置名；对话框改成聊天列表（最新在上，保留 5 句，旧的淡出）；斗蛐蛐的辅助等级改成和挑战 AI 一样的按钮加说明
- **实时思维链**：对局里可以打开「📜 实时思维链」，走棋请求改用流式输出（Anthropic 和 OpenAI 两种格式的 SSE 都支持），思考和回答边生成边显示在对话框顶部。服务商不支持流式参数时自动退回普通请求。本地转发和开发服务器的转发都改为边收边转
- **规则 AI 代走写进对话框**：原来"代走"的提示一直挂在对话框下面，下一步思考时还在，看起来像"失败了却没走"。现在作为一条带回合数的系统消息放进对话列表，写明代走了哪一步、为什么
- **关不掉思考的模型**：在当前接口上关闭思考的参数都不被接受时，对局里直接提示这个模型每步会比较慢，建议改用 OpenAI 兼容接口
